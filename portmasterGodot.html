Godot 4.3 no PortMaster

Guia de configuração, exportação e execução de um jogo Godot usando o runtime do PortMaster.

Sendo transparente: O DeepSeek ajudou a criar meus primeiros testes de bash, pois eram muito extensos. O trabalho foi humano, a IA, nesse caso, não fez trabalho criativo, apenas digitou texto. Mesmo assim, é desconfortável usar.

Nota sobre o aparelho: durante o teste, o arquivo control.txt identificou o dispositivo como RG351MP. Se o aparelho físico for um R36S, confira essa identificação antes de reutilizar esta configuração em outro sistema. O dado comprovado no teste é a resolução 640×480 e a arquitetura aarch64.

2. Configurações do projeto Godot

  • Versão: Godot 4.3. Use a mesma versão para editar e exportar o projeto.
  • Renderizador: Compatibility (compatibilidade), adequado ao caminho gráfico OpenGL ES usado no launcher.
  • Resolução-base: 640 × 480, proporção 4:3.
  • Linguagem: GDScript.
  • Saída: pacote de recursos teste_para_r36s.pck.

A resolução 640×480 foi lida do sistema. Ela é uma referência para o tamanho-base do jogo; o ajuste de escala e o modo de stretch dependem de como o projeto foi desenhado e precisam ser conferidos visualmente no aparelho.

3. Exportação no Godot

  1. Abra o projeto no Godot 4.3.
  2. Confirme em Project → Project Settings → Display → Window a resolução-base de 640×480, caso esse seja o layout desejado.
  3. Em Rendering → Renderer, selecione gl_compatibility / Compatibility.
  4. Abra Project → Export e configure o preset de exportação Linux/BSD compatível com o fluxo do projeto.
  5. Exporte o pacote de recursos como teste_para_r36s.pck (Export PCK/ZIP, quando disponível no preset).
  6. Copie o PCK para a pasta do port no cartão SD.
Importante: o launcher usa o executável Godot fornecido pelo PortMaster e passa o PCK com --main-pack. Portanto, neste fluxo, o arquivo principal do jogo é o PCK; não renomeie o executável do runtime. As opções exatas do preset de exportação não foram registradas nos testes originais e devem ser mantidas conforme o preset que gerou o PCK funcional.

5. Launcher Bash funcional

Salve como /roms2/ports/teste_para_r36s/teste_para_r36s.sh. O arquivo começa com #!/bin/sh, mas relança a si próprio com Bash porque o PortMaster pode chamá-lo por sh.

#!/bin/sh

if [ -z "$BASH_VERSION" ]; then
    exec /bin/bash "$0" "$@"
fi

GAMEDIR="/roms2/ports/teste_para_r36s"
LOG="$GAMEDIR/log.txt"

mkdir -p "$GAMEDIR"
exec > "$LOG" 2>&1

echo "======================================"
echo "INICIANDO JOGO GODOT 4.3"
echo "Data: $(date)"
echo "======================================"

# PortMaster
XDG_DATA_HOME=${XDG_DATA_HOME:-$HOME/.local/share}

if [ -d "/opt/system/Tools/PortMaster" ]; then
    controlfolder="/opt/system/Tools/PortMaster"
elif [ -d "/opt/tools/PortMaster" ]; then
    controlfolder="/opt/tools/PortMaster"
else
    controlfolder="$XDG_DATA_HOME/PortMaster"
fi

source "$controlfolder/control.txt"
get_controls

GODOT="$controlfolder/libs/godot_4.3.squashfs"
WESTON="$controlfolder/libs/weston_pkg_0.2.squashfs"

GODOT_DIR="/tmp/godot"
WESTON_DIR="/tmp/weston"

GODOT_BIN="$GODOT_DIR/godot43.aarch64"
PCK="$GAMEDIR/teste_para_r36s.pck"
GPTK="$GAMEDIR/teste_para_r36s.gptk"

# Verificar arquivos de runtime e jogo
echo
echo "Verificando arquivos..."

for FILE in "$GODOT" "$WESTON" "$PCK"; do
    if [ ! -f "$FILE" ]; then
        echo "ERRO: arquivo nao encontrado: $FILE"
        exit 1
    fi
done

# Preparar pontos de montagem
mkdir -p "$GODOT_DIR" "$WESTON_DIR"

# Montar Godot PRIMEIRO
echo
echo "Montando Godot..."

if [ "$PM_CAN_MOUNT" != "N" ]; then
    $ESUDO umount "$GODOT_DIR" 2>/dev/null || true
fi

$ESUDO mount "$GODOT" "$GODOT_DIR" || {
    echo "ERRO: falha ao montar Godot"
    exit 1
}

echo "Godot montado."

# Agora verificar o executavel
echo
echo "Verificando executavel Godot..."

ls -la "$GODOT_DIR"

if [ ! -x "$GODOT_BIN" ]; then
    echo "ERRO: executavel nao encontrado: $GODOT_BIN"
    exit 1
fi

echo "Executavel confirmado: $GODOT_BIN"

# Montar Weston
echo
echo "Montando Weston..."

if [ "$PM_CAN_MOUNT" != "N" ]; then
    $ESUDO umount "$WESTON_DIR" 2>/dev/null || true
fi

$ESUDO mount "$WESTON" "$WESTON_DIR" || {
    echo "ERRO: falha ao montar Weston"
    exit 1
}

if [ ! -f "$WESTON_DIR/westonwrap.sh" ]; then
    echo "ERRO: westonwrap.sh nao encontrado"
    exit 1
fi

echo "Weston montado."

# Preparar jogo
cd "$GAMEDIR" || exit 1

export XDG_DATA_HOME="$GAMEDIR/conf"
mkdir -p "$XDG_DATA_HOME"

# Controles
if [ -n "$GPTOKEYB" ] && [ -f "$GPTK" ]; then
    echo "Iniciando controles..."
    $GPTOKEYB "godot43.aarch64" -c "$GPTK" &
fi

# Executar
echo
echo "======================================"
echo "INICIANDO GODOT"
echo "======================================"

$ESUDO "$WESTON_DIR/westonwrap.sh" \
    headless noop kiosk crusty_x11egl \
    "$GODOT_BIN" \
    --rendering-driver opengl3_es \
    --audio-driver ALSA \
    --main-pack "$PCK"

GAME_EXIT=$?

echo
echo "Jogo finalizado. Codigo: $GAME_EXIT"

# Limpeza
$ESUDO "$WESTON_DIR/westonwrap.sh" cleanup

if [ "$PM_CAN_MOUNT" != "N" ]; then
    $ESUDO umount "$WESTON_DIR" 2>/dev/null || true
    $ESUDO umount "$GODOT_DIR" 2>/dev/null || true
fi

pm_finish

exit "$GAME_EXIT"

7. Problemas encontrados e soluções

  • source: not found: o PortMaster chamou o script com /bin/sh. Solução: relançar o script com /bin/bash antes de usar source.
  • failed to setup loop device: a montagem precisava dos privilégios configurados pelo PortMaster. Solução: usar $ESUDO mount e $ESUDO umount.
  • Executável não encontrado: o nome real dentro do runtime é godot43.aarch64, não godot_4.3.aarch64.
  • Verificação antes da montagem: o executável só existe em /tmp/godot/ depois que o SquashFS é montado. Por isso, montar primeiro e verificar depois.

8. Checklist para outro jogo

  • Usar Godot 4.3 para manter a versão compatível com o runtime testado.
  • Manter o renderizador Compatibility.
  • Exportar o PCK e conferir o nome usado no launcher.
  • Colocar PCK, GPTK e SH na mesma pasta do port, ajustando os nomes no script.
  • Confirmar a arquitetura e a resolução reportadas pelo sistema de destino.
  • Se houver falha, consultar log.txt na pasta do jogo.
